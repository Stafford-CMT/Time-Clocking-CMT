This is NOT a standalone Caddyfile. CMTDC01 (hostname CMT-DC) runs one shared
Caddy for all its apps, as the Windows service `Caddy` (through NSSM). Its
Caddyfile is:

    C:\IO BUDDY\IO Buddy - Eplan database import export\server\Caddyfile

Time Slide's block is at the end of that file (added 2026-11-03, live). Never
start a second Caddy -- it would fight the existing one for ports 80/443.

Ports on this server: IO Buddy 4000, Gantt 4001, MecHub 4002, Training Matrix
4003, Time Slide 4004 (PORT in C:\TIME SLIDE\server\.env). Check a port is
free with `netstat -ano | findstr :<port>`.

The block:

    timeslide.cliffeng.com {
        reverse_proxy localhost:4004
    }

No `tls` line, same as the iobuddy.cliffeng.com block: Caddy gets a public
Let's Encrypt certificate by itself (it did, 2026-11-03). That needs the
public DNS for timeslide.cliffeng.com to point at the same public address as
iobuddy, and ports 80/443 reaching this server, exactly as for IO Buddy.
(`tls internal` is only for internal-only names like the Gantt board's
`designplan`.)

Changing the Caddyfile, in PowerShell as administrator in its folder:

    Copy-Item Caddyfile Caddyfile.backup
    notepad Caddyfile
    C:\Caddy\caddy.exe validate --config Caddyfile
    C:\Caddy\caddy.exe reload --config Caddyfile

`validate` must say "Valid configuration" before you `reload`. The reload is
live: the other sites stay up. Ignore its "not formatted" warning and never
run `caddy fmt --overwrite` -- it rewrites the other apps' blocks.

DNS (done 2026-11-03, checked with nslookup):
  - internal, on CMT-DC: A record timeslide.cliffeng.com -> 10.0.0.254
  - public cliffeng.com DNS: A record -> 41.223.246.128 (same as iobuddy)
Microsoft sign-in return addresses on the Time Slide app registration:
  https://timeslide.cliffeng.com/auth/callback and .../login.html

To take Time Slide off the address: remove its block, validate, reload.
